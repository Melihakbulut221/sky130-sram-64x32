Every chip needs memory, and the densest memory you can build in plain logic is the six transistor SRAM cell.

In this video we design one from scratch, on SkyWater's open source 130 nm process, SKY130, using only open tools.

Here is the result up front.

A 2 kilobit memory macro, 64 words of 32 bits, with byte write enables.

The cell array is full custom layout, generated by Python code.

The logic around it is standard cells.

The layout passes the design rule checks of two independent tools, it matches its netlist transistor by transistor, and the extracted layout works in SPICE at the slow, typical and fast corners.

There is no fabricated chip yet, so everything you will see is simulation and sign-off.

The cell is two inverters connected in a loop.

The loop has two stable states, and that is the stored bit.

Two more transistors, the pass gates, connect the two sides of the loop to a pair of bit lines when the word line goes high.

To read, both bit lines are charged to the supply and the word line is switched on.

The side of the cell that holds a zero pulls its bit line down.

But while it does that, the pass gate lifts that zero a little.

If it lifts it too far, the cell flips, and the read destroys the data.

So the pull down transistor must be stronger than the pass gate.

Writing is the opposite fight.

One bit line is forced to zero, and the pass gate now has to overpower the pull up transistor that is holding the one.

So the pass gate must be stronger than the pull up.

One transistor, two opposite requirements.

The standard way to measure this is the butterfly curve.

Plot the transfer curve of one inverter, mirror the other one on top, and the largest square that fits between them is the static noise margin.

With the word line off, the margin is about 698 millivolts.

During a read it shrinks to about 372, and at the worst process corner to 218.

I swept the width of the pull down transistor over all process, voltage and temperature corners.

A wider pull down improves the read margin, in blue, and costs write margin, in orange.

The chosen cell uses a 0.65 µm pull down, minimum size pass gates, and high threshold pull ups, which also cut the leakage by a factor of ten.

Corners are not enough for a memory, because every cell has its own random mismatch.

A thousand Monte Carlo samples with the mismatch models of the process put the worst case read margin 23 standard deviations away from failure.

That is as far as the models can tell us; only silicon can confirm it.

Now the layout.

The cell follows the classic thin cell arrangement.

Two n type strips on the outside carry the pull down and pass transistors.

Two p type strips in a shared n-well in the middle carry the pull ups.

Two rows of polysilicon cross them.

One piece of poly is the gate of a pull down and a pull up at the same time, that is one inverter.

The short pieces at the left and right edges are the pass gates.

Commercial SRAM cells use special, tighter design rules.

This one deliberately does not.

It is drawn with the ordinary logic rules, so it needs no waivers.

The price is area: the two cross coupling wires need ordinary poly contacts, with ordinary spacing, and they sit in the middle of the cell.

The result is about twice the area of the foundry's own cell.

Metal one carries the word line across the cell.

Metal two runs vertically: ground on the cell boundaries, the two bit lines, and two supply lines over the n-well.

None of this was drawn by hand.

The cell is a Python function that writes rectangles in the Magic layout format.

Because the cell is point symmetric, each shape is described once and the code places it twice.

Neighbouring cells are mirrored, so they share their bit line contacts, their power contacts, and the contact of the word line.

Every sixteen rows there is a strap row with well taps and two power rails.

Sixty four rows of thirty two cells make the array macro: 12,288 transistors in 158 by 66 µm.

Word lines come out on the left, bit lines at the bottom, and vertical power straps on metal four tie into the rails.

The array is checked on its own before anything else is built on top.

Zero violations in Magic, zero in the KLayout deck that ships with the process, and the extracted transistors match the reference netlist uniquely.

An array is useless without the circuits around it: a decoder to pick a row, drivers to precharge and write the bit lines, and something to sense them.

Normally that means analog sense amplifiers and carefully tuned self timed pulses.

For a small memory at 1.8 volts I chose something much more boring.

The bit lines swing all the way from rail to rail, so a plain inverter can sense them.

And there are no internal pulses at all.

While the clock is high, the bit lines precharge and the address decodes.

While the clock is low, one word line is on.

If a phase is too short, you slow the clock down.

Nothing depends on a delay matching another delay.

Each bit line gets one standard tri state buffer that does three jobs.

It precharges the line, it pulls the line low for a write, and it works as a keeper: as soon as one bit line has fallen, the other one is actively held high.

Because of that keeper the memory is fully static.

You can stop the clock in either phase.

The one dangerous moment is the rising clock edge, when new inputs arrive while the old word line is still switching off.

Hold latches, opened by a delayed copy of the phase clock, block the new address and data until the previous access has ended.

The periphery is synthesized, placed and routed with LibreLane: Yosys, OpenROAD, Magic, KLayout and Netgen, with the array as a hard macro.

About 774 standard cells end up below and to the left of the array.

One surprise on the way: the clock tree tool followed the phase clock through the word line gates, onto the bit lines, and crashed.

A clock that ends in a memory cell is not what it expects.

So the phase clock is distributed by three hand placed buffers in the Verilog instead.

The finished layout is clean in both design rule checkers, has no antenna violations, and passes the timing checks of the flow.

Then I extract the whole layout again down to transistors, array and standard cells together, and compare it with the source netlist.

18,248 devices, and the circuits match.

The real test is SPICE on the extracted layout, with every transistor and the parasitic capacitance of every wire.

Here a word is written and read back.

After the falling clock edge the word line rises, the cell pulls one bit line all the way down, the inverter senses it, and the output latch updates 2.5 nanoseconds after the clock edge.

The same sequence passes at the slow, typical and fast corners.

At the slow corner the data is out 5.0 nanoseconds after the clock edge, and the memory still works with an 11 nanosecond clock.

The data sheet specifies 13.8, to leave a margin.

So what is in the repository?

The layout, the abstract, timing libraries for three corners, a simulation model, the netlists, and a self test that runs a march test over all the words.

What is missing is the most important step: silicon.

Clean sign-off and passing simulations make a design ready for a test chip, not proven.

Three things I take away.

First, robust beats clever: for a small memory, full swing bit lines and two clock phases remove a whole class of timing risks.

Second, design rules shape the circuit: without the special contacts of a foundry cell, the cross coupling wires decide how big the cell is.

And third, verify every level on its own, and then everything together.
